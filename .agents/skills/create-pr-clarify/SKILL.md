# Issue 確認付きプルリク実装

[create-pr](../create-pr/SKILL.md) をベースに、実装前に Issue の不足・不明点を解消してからプルリクを作成する。

- README.md は書き換えない。
- Issue 番号（`#` で始まる番号）が必須。指定がなければユーザーに Issue 番号を確認する。

## ワークフロー

```
- [ ] 1. Issue を読む
- [ ] 2. 不足・不明点を抽出する
- [ ] 3. ユーザーにまとめて質問する
- [ ] 4. 回答を Issue 本文に統合する
- [ ] 5. create-pr の手順で実装・プルリク作成する
```

---

## 1. Issue を読む

- 指定された番号の Issue を取得する。
- Issue 本文・コメント・ラベルを踏まえ、実装に必要な情報が揃っているか確認する。

---

## 2. 不足・不明点を抽出する

- 実装判断に影響する不足・曖昧さだけを抽出する。既に Issue に明記されていることは質問しない。
- 抽出結果は内部メモとして整理する。
- 不足・不明点が0件と判断できる場合は、ステップ 3〜4 をスキップしてステップ 5 へ進む。

---

## 3. ユーザーにまとめて質問する

質問は1回のメッセージにまとめる。AskQuestion が使える場合は構造化して提示する。

### 質問の書き方

- 各質問に背景（なぜ必要か）を 1 行添える
- 選択肢がある場合は推奨案を明示する

## 4. 回答を Issue 本文に統合する

ユーザーから回答を得たら、Issue 本文を更新する。

### 統合ルール

回答は別セクションに追記せず、既存の Issue 本文そのものに組み込む。更新後の Issue 本文だけを読めば要件が完結する状態にする。

## 5. create-pr の手順で実装・プルリク作成する

[create-pr](../create-pr/SKILL.md) に従い、更新後の Issue 本文を実装の唯一の要件ソースとして作業する。
